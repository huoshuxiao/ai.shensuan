## 1. 项目定位

用 RD-Agent 自动挖因子、用自研三环裁判链验证、用 Streamlit 把结论交给人判断。

- **交付形态是"名单"，不是"下单"。** 股票线收盘后出「剔除域 + 50 只观察名单 + 5 只下单顺序
  名单」，成交由人手工录回；ETF 线同样不接下单，只跑研究 / 回测 / 影子盘（看板末节 09-27 起
  叫「影子盘监控」，旧名「实盘监控」读起来像在替人下单）。
- **两条线口径严格隔离**（本项目最重要的工程约束，见 §15）：股票线与 ETF 线各有一份数据底座、
  各一份 qlib bin、各一套 RD-Agent 提示词与阈值文档，**措辞与结论互不外溢**。
- **曾有过第三条线（live2etf，09-27~09-30）**：只出状态格读数、无判据、无下单、**从未进 git** ⇒
  09-30 由用户本人整支删除，磁盘与文档都不再有这一支（本条留着只为了说明"为什么别处找不到它"）。
  §15 那条隔离规则现在**只对两条线成立**；早先正文里「见 §19」指的也是这一支，那一节从未进这份文件。
- LLM 只负责"想"（提假设、写表达式、自述理由），**裁决权在裁判链**（§8/§9），人工负责"决"。

### 3.1 qlib 的真实出场面：五处（逐条 grep 实测，不是规划）

旧措辞「只用它的数据格式」把边界写窄了。实测用到的是**格式 + 日历 + 面板生成 + Alpha158 特征器 +
容器内的标准回测**，自研换掉的只有最上面那一层「判据」。

| qlib 的哪一块 | 在本项目干什么 | 落点 |
|---|---|---|
| 数据格式 `.bin` + `instruments` | 行情唯一载体，两线各一份、互不共享 | §2 架构图、§6.3 增量范式 |
| **交易日历** `calendars/day.txt` | 「今天该补哪一场」由它定；休市与未来场次挡在抓数之前 | `run_ashare_daily_chain.py:162`（§7 的 `decide_session`） |
| **面板生成器** | conda env 里 `qlib.init` + `D.features(D.instruments(), …)` → `daily_pv.h5`，**下游全链路都从这份取数**；落盘＝写同目录 `.part` → 回读元数据核形状 → `os.replace` 原子换名 ⇒ 中途被 OOM 砍也不留半截面板（09-29） | `common/rdagent_docker/pregen_source_data.py:96,165` |
| **Alpha158 特征器** | 09-26 全市场 157 条候选的表达式来自 `Alpha158DL.get_feature_config()` | `stock/v1/temp/alpha158_scope_0926.py:18` |
| **标准回测本身** | RD-Agent 容器 `local_qlib` 里每次候选评估都是 qlib 的回测；回收的 IC / ICIR / 年化挂在 `experiment.result` 上 | `common/src/core/rdagent_driver.py:108` |

**为什么判据层自研**：这个系统的产出物是**一份带硬闸的名单**（50 只观察 + 5 只下单），不是一条净值
曲线。qlib 的策略层只有 `TopkDropoutStrategy`（topk + 换手惩罚），表达不了这里的关键形状 —— 板块限幅
三档（`flat/board/dated`）、剔除的两处强度、配额档「空出来的席位回填谁」、下单层的贪心扫描。那张
三档闸门 A/B 账单本身就是自研才做得出的实验。附带一笔环境收益：16G 单机上常驻看板与 rdagent/pyqlib
的依赖树隔离（§5.1）。

**自研欠的账 —— 对拍只兑现了一条**：
- 截面那层 ✅ 与 qlib 同公式：`run_ashare_factor_eval.py:13` 把 Pearson 截面 IC 定义成「qlib 报表里的
  IC」，用来对齐沙箱报出的 0.029。
- 组合层 ❌ **没有对 qlib 的等价性检验**。而且 DSR / PBO / walk-forward 这三件 qlib 根本没有，全自研
  ⇒ 实现错了只能自己发现（ETF 线那条链接进来初期三条恒不产生信息：DSR 恒 0、`n_trials` 恒 3、折级
  PBO 恒 0.9444）。已列为 §18 第 10 条。
- 继承的坑也要记：选了 qlib bin 就继承「前复权锚在上市首日、append 挪不动历史、假台阶永久」（§6.2），
  自研 CSV 反而能整段重算。

### 5.1 三个 Python 环境，别混

| 用途 | 解释器 | 说明 |
|---|---|---|
| 日更 / 裁判链 / 看板 | `/usr/bin/python3.10` | 默认 `python3` 是 3.8.10，**必须显式指名 3.10** |

## 6. 数据规范

### 6.1 数据源优先级（写死实测可用性）


批量收盘快照 5,567 行含北交所；**快照只有价量 14 列 ⇒ 本机没有基本面 / 估值 / 市值通道**。
需要财务数据的判据一律不做（不是推迟，是数据前提不成立）。**不使用 Tushare**（无 token）。

### 6.2 口径（改动会挪动历史结论）

- **复权**：qlib bin 的前复权**锚在上市首日**，追加新数据挪不动历史；台阶是永久的，靠
  `RET_LIMIT` 假台阶护栏兜住（股票线单格 0.30、ETF 线 0.35 置 NaN）。
- **`$volume` = 真实手数 / `$factor`** ⇒ 它带一个每票可任意缩放的常数。任何用它的判据都要先问
  「换真手数口径会不会翻」（已实测：剔除侧只差 0.2pp，多头排序侧 top5 重合中位 0%）。
- `amount20 = $close × $volume × 100` 是**真钱**口径（全市场约 2.14 万亿/日）。
- **交易日历以 qlib `calendars/day.txt` 为准**，不按自然日、也不以 AkShare 为准（原蓝图这条已否）。
- 盘面价 = 复权价 / `$factor`；账本估值用盘面价而非盘中价，分红必须手工记成入金。

### 6.3 增量更新范式（不许删了重拉）

日更只做**贴新行 + 幂等**：源不可达时沿用旧缓存并自报，判据单点复用，落盘前自动备份被覆写的
bin，四道闸按发作顺序（**场次已经发生**=休市日/未来场次在抓数前就拒 → 15:00 收盘闸 →
昨收↔bin 末格对齐率 ≥98% → 代码前缀白名单，`update_qlib_bin_daily.py:118-120,306`）。
缓存复用也上这把尺子：目录里已经躺着的脏快照（钉着未来场次、改名拷进来的）先抽样对表、
不过就重取（`align_against_bin`，`:190`）——收盘行占比只判得出「是不是收盘后抓的」，判不出是哪一天。
指数基准只写 features、不进 instruments。

### 9.4 排序轴「要不要换回旧轴」：两层各赢一半，钱只落在下单层（09-28 量完，**维持现轴**）

`STD($volume,20)`（旧轴，09-24 之前用）与 `SMA($volume,20)`（现轴）是同一簇的两个代理
（截面 spearman 0.93~0.95），所以这桩争论只关乎「在同一个信号上取哪个代理」，不关乎新信息。
09-28 把两条轴放到**同一套时序、同一份配额名单、同一 5 席下单层**上并排量了一遍
（驱动 `stock/v1/temp/axis_ctrl_quota_0928.py`，产物只落 `stock/v1/temp/tmp_axis_ctrl_0928/`，不进 git；
驱动逐位复现了归档那两格 —— 全局档「五十只全买」+0.0155（M3 参照行）、下单层 0.130379 ——
才敢和 §11 的账单直接比）：

- **篮子层（整张 50 只全买，不经过下单层）：旧轴三档全胜** —— top50/100/200 是
  +1.00%/+1.73%/+3.69% 对现轴 +0.11%/+1.25%/+1.54%。这一层是打分用的地板，不是真能买的东西。
- **下单层（真掏钱那一层，配额·5 席·满仓）：现轴赢 3.34pp/年** —— +13.04% 对 +9.70%，
  同时最大回撤更浅（−53.57% 对 −55.02%）、单程换手更低（0.270 对 0.443）、每场换人更少
  （1.34 席对 2.20 席）。旧轴只赢一列：**真下单那 5 只的 20 日均额更大**（旧轴 6.79e7 对现轴
  5.81e7，更好成交）。
- **10 席那一档确实旧轴反超**（+5.09% 对 +0.31%），但两轴都凑不满：现轴只有 12.81% 的天数填满
  10 席、旧轴 10.53% ⇒ 那一档不是一个可执行的选择，别拿它当换轴的理由。
- **换排序轴不会连带换闸门覆盖面**（探针 `stock/v1/temp/gate_axis_probe_0928.py`）：两条轴在
  全面板 17,808,968 格里 NaN 位置**零差**，第 1 道闸「因子有值」在两种写法下逐格相同
  ⇒「闸门也跟轴」这一档不是省了一笔钱，而是根本没有这笔钱（三套配置跑出来逐格相等）。
  ⚠️ 探针第一次拿 `ts_std(volume,5)` 当对照是**无牙的**：它相对 20 日窗多出来的覆盖全是
  上市 <60 天的新票，被次新闸 `ASHARE_PORT_MIN_LISTED=60` 吃掉，两臂恒等 ≠ 证住了什么。
  正对照要选在「差异能活到判据那一层」的位置，这里换成 `ts_std(volume,250)` 才有牙。

结论：**维持 `SMA($volume,20)`，判据一行未改**（本轮产品代码 0 行变动，只有注释）。
边界照旧要说清：轴是全样本挑的 ⇒ 上面全是**样本内**读数。**同一格下单层账单**上，近六年
（2021 起）现轴 3/6 年为正、均值 +12.92%/年，旧轴 4/6、+12.20%/年 ⇒ 这一列读不出方向差；
「扔掉最好的那一年还剩多少」现轴 +120pp 对旧轴 +75pp（11 年累加）⇒ 现轴赢的不只是平均，

docstring 里那句「分年度现轴 9/12 为正、2021 起 4/6 为正、均值 +2.1%/年」是**篮子层**

## 11. 组合与下单层

**观察名单（50 只）先由形状开关决定谁有资格进**：默认 `quota` = 四段各留席位（主 20/创 10/
科 10/北 10）后按安静度排、缺货回填（见 §9.1）。这条**不是笔改进，是一笔交易**（09-25 用户
裁）：5 席下单层 +11.70% → **+13.04%/年**、5 席凑满率 75.3% → **100%**；代价是 50 只篮子
**本身**的历史超额 +1.55% → **+0.11%/年**（IR +0.12 → +0.01），且名单 12 年平均 20 日均额
从 0.947 亿降到 0.772 亿（配额从三段捞进来的票更薄）。机制：配额花「安静度」买「板块分散」，
尾部代价摊满整张等权篮子、前排十几个恰好喂到 5 席层。真实身份 = **给创业板留 10 个保底席位**
（回放 570 天里科创板 570 天、北交所 494 天填不满 10 席，单板块占比中位只 0.94 → 0.80）。
⇒ 用法钉死：**前排 5~15 只拿来下单，整张 50 只拿来人工复核，不许当一篮子买**。
（当日实盘名单可能把科创/北交席位填上，而回放说这两段天天没货 —— 那是「570 天均值」与
「今天这一天」的差别，不是账单错。）

`order_candidates`（股票线）：在上面那份名单上按名次扫到 5 只，同板块 ≤3、同行业 ≤1、
**权重等权满仓 = 每只 1/实际挑到的只数**（09-25 由「每槽 20%、凑不满留现金」改过来：
**在全局前 50 那批名单上** 570 个调仓日有 24.7% 凑不满、平均 6.6% 资金闲置，换满仓后历史
超额 +9.90% → +11.70%/年而最大回撤不变 ⇒ 现金没买到安全；代价是只挑到 3 只时每只 33%）。
换成配额名单后回放里席位天天凑满，但**当日实盘照样可能缺票**（缺口只会来自那两条分散约束
——同板块 ≤3、同行业 ≤1——在队首顺延仍凑不满 5 只；⚠️ 09-27 实测纠过一次归因：**不是**执行闸
剔涨停 —— 那道闸在 5 席层 570 场里 98.9% 一只都不换、全历史只换过 9 个席位，09-23/24 两场
`n_picked=5, shortfall=0`，见 §9.1），所以那条警告不是纸面的。
判据本身**不自动放宽**。它的历史回放账单有（上面那串数就是，
`data/results/order_layer_*0925*.csv` 与 `quota_watchlist_m4_0925.csv`），但**样本内、
未过准入链**：它给的是「按这套分散约束下会是什么结果」，不是收益承诺。

**个人事实（影响设计，别再重新发明）：账户科创板 / 创业板 / 北交所均有权限。**
⇒ 任何"段约束"只能是**分散度**，不能是**排除**（行业未知的票不参与行业去重，否则等于用数据
缺口代理排除北交所）；跨板块涨幅水平不可比（限幅 ±10/20/30），提示词已写明不得提"把某段筛掉"
类因子，优先票级自归一构造。

## 14. 工程约定

- **Git**：实际提交是中文自由格式；因子库由 `common/src/optimizer/factor_library_git.py` 自动
  提交为 `[factor-lib] 因子库更新: N 总 / M 活跃`，**这笔 `git commit` 带 pathspec**（`-- <3 个库文件>`）：
  两线同处一个仓库，不带路径的 `git commit` 会把整个暂存区签掉（09-27 实测吞过一笔 10 文件的改动）。
  **原蓝图的 `feat:/fix:` 前缀未采用**。
  **未经用户明确要求不得 commit / push。** 个人成交与持仓（`*/data/live/`）不入库。
- **测试**：`etf/v1/tests` 21 文件 / 240 用例（09-29 13:28 实测：全跑 rc=0；09-29 00:36 那场是 20 文件 / 236）。
  覆盖 admission、边界闸、RD-Agent 接线、DSR、重挖触发、风险面板、DSL、回测风控、
  因子库自动提交的收窄面。**股票线 0 测试**（§18 第 1 条）。
  判据类改动必须占一个回归位；一次性验证脚本进 `*/v1/temp/`。
- **验证标准**：探针不算验证，**必须真实 e2e 跑通失败路径**；断言不许恒真；`sleep` 后的活体
  探针要先问那一拍有多长。
- **监控长跑任务只读**：不 kill 被监控进程 / 容器、不改配置；判断卡死看字节数 + 子进程 +
  `/proc/*/stat` 的 utime；超时收尾后要查旧 driver 是否托孤（父进程变 1）再报并发写风险；
  ETA 只从当轮产物反推；进程终态后只回一行。
- **并发多会话改同一批文件是常态**（不是事故）：动任何 `src/` 文件前先重读当前内容，落盘前先
  `cp` 将被覆写的产物到本线 `temp/`，动手后把差异报清楚；覆写面 / 失败分支要先报再动手。
- 类型注解与 ruff/black **尚未接入**（无 `pyproject.toml`、无 pre-commit）。

## 17. 常见陷阱（全部是本项目实际踩过并留下证据的）

| 陷阱 | 后果 | 规避 |
|---|---|---|
| 未来函数 | 回测虚高 | 严格时序切分 + 信号 T 日收盘、成交 T+1 |
| 同一份样本挑最好的一行 | 结论是噪声 | 加规则必带样本外；报告名次而非极值 |
| `$volume` 当量价真值 | 排序可被每票常数缩放 | 尺度敏感判据要过"真手数口径"复核 |
| 复权台阶 | 历史被移动 | 锚在上市首日 + `RET_LIMIT` 护栏 |
| 两线提示词互抄 | 模型拿对面先验当本线事实 | §15，只有 DSL 文法共用 |
| 候选试算写权威 csv | 后两环输入被换口径 | `route()` → `*.cand.csv`（§8.3） |
| 同一张表混两种涨停闸 | 读数错而无人知 | 产物必带 `gate` 列、另存 `_flat/_dated` |
| 拿 ④ 审计的「挤进前 50」列当这道闸的影响面 | 它是松界，历史上当尺子用**高估约 25 倍** | 要数真换了几个席位就关闸重跑整条漏斗（§9.1） |
| LLM 写进联合优化的风控数 | `daily_stop_loss>0` 让止损静默失效 | `RISK_BOUNDS` + `sanitize_live_risk` |
