## 1. 系统概览

系统的核心工作流是一条闭环：

```
数据(akshare) → 因子挖掘(注册表/LLM/GP/多目标GP/混合) → 因子库+聚类去重
   → 正交化(LLM 调参/联合优化) → 信号 → 回测(日线/分钟线)
   → 稳健性验证(Walk-forward/PBO/多策略) → 分析(衰减/归因/SHAP)
   → 闭环(衰减监控→触发→自动重挖) → 实盘信号 → 实盘反馈 → 报告/评估
```

- 全部代码在 `etf/v1/src/` 下，**所有命令都在该目录执行**；
- 频率由环境变量 `ETF_FREQ` 控制（`daily | 1min | 5min | 15min | 30min | 60min`）；
- 每个研究环节由 `src/config/config.py` 中对应的 `enabled` 开关控制，单独环节失败不会中断主回测（打印 ⚠️ 后继续）；
- LLM 相关能力（因子假设、变异/交叉、正交调参、报告生成与评估）在未配置 API Key 时自动降级为规则/模板路径，不会报错。

## 2. 安装与环境准备

### 2.1 依赖

```bash
# Python ≥ 3.10（akshare 新版不再支持 3.8/3.9）
cd etf/v1
pip install -r requirements.txt
```

| 依赖组 | 用途 | 缺失时的影响 |
| :--- | :--- | :--- |
| pandas/numpy/scipy/scikit-learn | 核心计算 | 必需 |
| akshare | 行情数据 | 必需（无法拉数据） |
| plotly/streamlit | 看板 | 看板不可用 |
| openai + tenacity | LLM 能力 | 全部 LLM 环节降级为模板/随机 |
| statsmodels | 衰减 ARIMA 预测 | 衰减预测环节跳过 |
| lightgbm/shap | 衰减 SHAP 解释 | 自动降级为 lag_corr 解释 |
| kaleido/imageio(Pillow) | 动画 GIF/MP4 导出 | 仅保留 HTML 动画 |
| schedule | 定时任务 | scheduler.py 不可用 |
| xtquant(easytrader) | 实盘下单 | 仅可用 paper 模式 |

### 2.2 API Key（可选但推荐）

```bash
export OPENAI_API_KEY=***       # 主 LLM（config.LLM_API_KEY_ENV）
export DEEPSEEK_API_KEY=***  # 多模型日报
export DASHSCOPE_API_KEY=***     # 多模型日报
# 本地 LLM（Ollama / vLLM / LM Studio 等 OpenAI 兼容端点），配置后全系统 LLM 调用改走本地：
export ETF_LLM_BASE_URL=http://localhost:11434/v1   # 留空=OpenAI 官方端点
export ETF_LLM_MODEL=qwen2.5:14b                   # 本地模型名（不设则沿用 gpt-4o-mini）
```

本地服务不校验 key，`ETF_LLM_BASE_URL` 配置后即使无 `OPENAI_API_KEY` LLM 环节也视为可用；运行日志会打印 `LLM 端点: 模型=… 端点=…` 供核对。RD-Agent(Q) 官方循环自带体检：`rdagent 包/conda/docker/pyqlib/LLM` 逐项 ✅/❌ 写入日志，依赖齐备即真正执行 factor 循环，缺失则记录原因并降级本地挖掘管线（不会刷 traceback）。

### 2.3 数据缓存与多数据源

首次拉取行情后缓存于 `etf/v1/data/cache/`（含 `etf_universe_cache.csv` 池缓存与 `etf_list_dates.json` 全市场上市日期缓存——按"最早上市"选指数代表需先知道所有候选的上市日期，首次构建逐只拉取约十几分钟，之后增量补拉），重复运行不再请求网络。删除缓存即强制重新拉取。所有运行产物/实盘记录/因子库也统一写入 `etf/v1/data/` 下，`src/` 只保留代码；目录根路径可用环境变量 `ETF_DATA_DIR` 覆盖。

行情按 `config.py` 的 `DATA_SOURCES` 优先级自动降级：**日线 东财→新浪→腾讯、分钟线 东财→腾讯、ETF 列表 东财现货→新浪现货→内置兜底池**。日志出现 `🔁 已降级到数据源 [sina]` 即表示主源失败已自动切换；仅当全部源失败才打印 `❌` 并跳过该标的。

### 2.4 运行日志

每次运行在 `etf/v1/log/` 生成 `{tag}_{日期}.log`（如 `research_daily_20260919.log`、`feedback_*.log`、`live_*.log`），逐行带时间戳，自动保留 30 天；目录可用 `ETF_LOG_DIR` 覆盖。排查：`grep -E "⚠️|❌|Traceback" etf/v1/log/research_daily_*.log`。

## 3. 第一次运行：日线回测

```bash
cd etf/v1/src
python3.10 run_daily_backtest.py
```

- 回测区间：`2010-01-01 ~ 当天`（`config.py` 的 `BACKTEST_START/BACKTEST_END`；`BACKTEST_END` 未设置或为空时自动取运行当天，也可用环境变量覆盖）；
- 结束标志：控制台打印 `🎉 完成！` 与绩效表；
- 产物：`equity_daily.csv`、`trades_daily.csv`、`signals_daily.csv`、`dsr_daily.csv`、`optimized_params_daily.json`、`factor_clusters.csv`、`factor_attribution.csv`、`factor_decay_predict.csv`、`multi_*.csv`、`walk_forward_daily.csv`、`pbo_result.json`、`pbo_timeline.csv`、`equity_daily.png`、`factor_library.md` 等（见第 6 节）；
- 数据接口偶发连接重置时会自动降级到备用数据源（见 2.3），全部源失败才跳过该标的；完整过程记录在 `etf/v1/log/research_daily_*.log`（见 2.4）。

## 4. 分钟线回测与双频率对比

```bash
cd etf/v1/src
python3.10 run_minute_backtest.py     # 分钟线全流程
python3.10 compare_freq.py            # 对比 + 持仓相似度
```

`compare_freq.py` 输出：

- 终端打印两种频率的绩效表；
- `data/results/freq_comparison.csv`：总收益/年化/波动/夏普/最大回撤/交易次数对比；
- `data/results/holdings_similarity.json`：**持仓相似度**——从 `signals_daily.csv` 与 `signals_1min.csv` 提取每日收盘持仓（当天最后一个非空 `target_code`），按日期对齐后计算：

| 指标 | 含义 |
| :--- | :--- |
| 对齐天数 | 两频率都有数据的交易日数 |
| 总相似度 | 全部对齐日持仓一致比例（含双空仓） |
| 持仓日相似度 | 至少一个频率持仓的日子中的一致比例 |
| 双边持仓日相似度 | 两个频率同时持仓时**选股一致**的比例 |
| 持仓占比_a/_b | 日线/分钟线各自的持仓时间占比 |
| 不一致示例 | 最多 20 条分歧日明细 |

> 解读：分钟线理论上应还原日线方向。双边持仓日相似度低 → 因子对 bar 粒度敏感，策略频率可迁移性存疑，需复核。

## 5. 研究主流程（9 个阶段）详解

`main.py`（经 `run_daily_backtest.py` / `run_minute_backtest.py` 启动）共 9 步，各步与 config 开关：

| 步骤 | 内容 | 控制开关（config.py） |
| :--- | :--- | :--- |
| 1 | 构建 ETF 池：按"指数成分"选取——ETF 名内嵌的跟踪指数分组，每指数取**上市最早且流动性达标**的一只代表（同日按成交额取大者；上市不满 1 年即 `min_list_days=365` 天的不入池），再截 `max_count`。取最早上市者让每只代表承载最长历史，缓解早年回测空仓偏差（旧"现货快照 Top-N"与固定兜底池已弃用，兜底仅在行情源全挂时） | `ETF_FILTER` |
| 2 | 按频率加载行情（缓存） | `FREQ`/`ETF_FREQ` |
| 3 | 因子挖掘：`RDAGENT_BACKEND="official"` 优先走微软 RD-Agent(Q) factor 循环（前置体检逐项写日志，依赖缺失即 ℹ️ 说明原因并降级）；随后注册表基线 + 多源(LLM/官方/simple/GP) + 单目标 GP（LLM 研究计划提供种子、LLM 变异/交叉算子；最佳 \|IC\| 连续 `stagnation_generations` 代无提升早停）+ 多目标 GP(NSGA-II，RL 权重调度，同早停) + LLM-GP 混合。未配置 LLM 时模板挖掘为确定性单次循环，不再重复 3 遍 | `RDAGENT_BACKEND` `MULTI_SOURCE` `GENETIC` `LLM_RESEARCH_PLANNER` `LLM_MUTATION` `LLM_CROSSOVER` `GENETIC_MULTI_OBJECTIVE` `EXTENDED_OBJECTIVES` `DYNAMIC_WEIGHTS` `ADAPTIVE_MUTATION` `RL_WEIGHT` `LLM_GENETIC_HYBRID` |
| 4 | 因子库入库（Markdown+索引+git 提交）→ 层次聚类与代表去重 | `FACTOR_LIBRARY` `FACTOR_LIBRARY_GIT` `FACTOR_CLUSTERING` |
| 5 | 正交化：LLM 联合优化（正交+风控参数，按 DSR 迭代）> LLM 正交调参 > 默认 gram_schmidt | `JOINT_LLM` `ORTHO_LLM` `ORTHOGONAL` |
| 6 | 因子加权（IC-IR 风险预算）→ 轮换策略生成 bar 级信号 | `RISK_BUDGET` |
| 7 | 回测（含滑点/佣金/风控熔断）→ DSR 显著性 | `DSR` `RISK_CONTROL` |
| 8 | 稳健性验证：Walk-forward 分折（**折内按 `fold_engines` 重新挖因子**，与主链同构，默认 `["registry","genetic"]`；逐折打印训练/测试区间、可用标的数、挖出因子与跳过原因，产物列「折内因子数/折内因子来源」）+ 策略级 PBO（**配置族默认取真实回测过的风控参数组合**：终态因子集 × OFAT 参数邻域逐档重跑回测，`use_config_family: False` 时退化为单一净值的波动率降权伪变体；日志与 `pbo_result.json` 标出 `配置族=real×N` / `pseudo×6`）+ PBO 演化时间线 + 多策略并行（生命周期/衰减/组合） | `WALK_FORWARD` `PBO` `STRATEGY_PBO`（`use_config_family`/`max_family_configs`）`PBO_TIMELINE` `MULTI_STRATEGY` `STRATEGY_LIFECYCLE` |
| 9 | 分析与闭环：衰减预测(ARIMA/LightGBM) → SHAP 可解释 → SHAP 时间线 → 归因 → 衰减监控 → 双指标触发 → 自动重挖。双指标触发（DSR/PBO）与重挖节流（冷却、最大轮数）**共用 `data/cache/remining_state.json` 的跨运行状态**并按频率分桶，连续恶化轮数跨进程累加、Δ 基准取自上一轮落盘值；触发后按 `remining_engines` 重挖。归因为 MC 置换 Shapley（每个因子子集重跑一次回测），算力上限由 `n_samples` 与 `eval_window_bars`（只截最近 N 根 bar 评估，日频=500）共同决定，可用 `method: "leave_one_out"/"marginal"` 降级提速 | `DECAY_PREDICT` `DECAY_EXPLAIN` `LLM_SHAP_EXPLAINER` `FACTOR_ATTRIBUTION` `FACTOR_DECAY` `TRIGGER_LOGIC` `AUTO_REMINING` `REMINING_STATE_FILE` |

阶段产物文件名对照见第 6 节。关闭重环节以加速：如只想看基线回测，把 `MULTI_SOURCE/GENETIC/GENETIC_MULTI_OBJECTIVE/LLM_GENETIC_HYBRID/MULTI_STRATEGY/WALK_FORWARD` 的 `enabled` 改为 `False`。

## 8. 实盘 / 纸面盘

```bash
cd etf/v1/src
python3.10 run_live.py                        # 默认：模拟盘 paper + ETF 池缓存标的
python3.10 run_live.py --codes 510300,510500 --mode paper
```

- **研究→实盘衔接（两处，缺一不可）**：
  1. **参数**：启动时读取 `data/results/optimized_params_{freq}.json`（第 9 阶段落盘的研究调参产物），按语义映射覆盖 `LIVE_RISK`——`single_position_max`→`max_position_ratio`、`max_trades_per_day`→`max_orders_per_day`、`cooldown_days`×24×60→`cooldown_minutes`（实盘熔断按挂钟时间 `now + timedelta(minutes=…)` 判定，研究按交易日计数，故把夜间/周末整日计入，风控口径宁长勿短），日止损/回撤熔断同名直取；`min_bars_between_trades` 无对应项（实盘按 tick 轮询而非按 bar 推进）。启动日志会逐行打印 `风控 xxx: 旧值 → 新值（研究调参）`；产物缺失时打印 ⚠️ 并沿用 `config_live` 默认值；
  2. **信号**：复用因子库（`data/library`）Top-10 活跃因子对订阅标的打分，权重取研究侧 ICIR 权重（`score = Σ |wᵢ|·符号(ICᵢ)·tanh(因子值) / Σ|wᵢ|`，权重缺失则等权，实盘无历史窗口故不做时间序列 z-score），取最大者；因子库为空会拒绝启动并提示先跑 `main.py`；
- 券商通道统一接口 `BrokerInterface`（`live/broker_interface.py`），三实现：`paper`（内置纸面撮合，跨平台，**默认**）、`qmt`（miniQMT/xtquant，需 Windows 客户端）、`easytrader`（同花顺等通达信系下单器，需 Windows）；
- `--mode` 不传时沿用 `config_live.ACCOUNT["broker"]`（默认 `paper`）；`--live` 标记实盘、且需再 `--auto-order` 才真实下单，否则一律 dry-run（订单状态 `DRY_RUN`）；
- 券商账号在 `src/live/config_live.py` 的 `ACCOUNT` 配置；行情快照/风控（单量、频率、滑点、止损熔断）由 `LIVE_RISK` 统一接管；
- `paper` 模式成交记录写入 `data/live/`（订单、持仓、归因快照、风控事件），供第 9 节反馈分析消费；
- 定时执行：`python3.10 scheduler.py`（每交易日 15:30 反馈+日报、每周一重训、约每月复盘；间隔可按文件内注释调整）。

## 9. 反馈闭环与报告评估工具链

```bash
cd etf/v1/src
python3.10 run_feedback.py                    # 滑点/逐笔分解/延迟/换手/策略/因子反馈 → report/feedback_report.md
python3.10 run_feedback.py --auto --llm daily # 回写建议滑点 + 生成 LLM 日报
python3.10 run_feedback.py --self-eval        # 报告自评（打分 + 问题聚合）
python3.10 run_feedback.py --optimize-prompt  # 依自评结果 LLM 改写提示词（先 --self-eval）
python3.10 run_feedback.py --vote-eval        # 多 LLM 投票评估历史日报
python3.10 run_feedback.py --blind-eval       # 多模型日报盲评排名
python3.10 run_feedback.py --ab-test          # 提示词 A/B（B 胜且 --ab-apply 时自动应用）
python3.10 run_feedback.py --blind-spot       # 盲区检测（报告遗漏项）
python3.10 run_feedback.py --monthly --quarterly --annual   # 月/季/年复盘
python3.10 run_multi_gen.py                   # 多 LLM 并发写日报 → 互评投票 → 胜出版入 report/report_daily.md
python3.10 run_monthly.py --days 20           # 单独月度复盘
```

反馈主链共 6 步：`[1/6]` 滑点（实盘价 vs 回测假设价）→ `[2/6]` **实盘 vs 回测逐笔分解**→ `[3/6]` 延迟 → `[4/6]` 换手 → `[5/6]` 策略级 → `[6/6]` 因子级。

第 `[2/6]` 步与滑点分析的分工：滑点以「同向最后一笔回测价」为基准，只回答"执行贵了多少"；逐笔分解以「时间上最近的一笔回测成交」为基准并给出时滞 `lag_days`（正=实盘晚于回测），用来区分分歧来自成交价还是成交时点。价差口径一致（正数一律代表执行劣于回测假设：买贵 / 卖贱）。明细落 `data/live/live_vs_backtest.csv`，汇总（配对笔数、平均|价差|、平均/最大时滞、时滞>1 天占比）进 `feedback_report.json` 的 `live_vs_backtest` 字段与 `report/feedback_report.md`；无实盘记录时打印 ℹ️ 并跳过，不影响后续步骤。

提示词文件在 `src/report/report_prompts.py`，被 `--ab-apply/--optimize-prompt` 改写前会自动备份到 `prompt_backups/`。

`--llm daily` 除写 `report/report_daily.md` 外，还会在 `data/live/` 落带日期的快照 `report_daily_YYYYMMDD.json`（日报正文）与 `feedback_report_YYYYMMDD.json`（原始反馈数据）——`--self-eval` / `--blind-spot` 即按这两个快照扫描打分（客观分 0-100，LLM 未配置时用规则分）。所有依赖 LLM 的子命令（self-eval 之外的 vote/blind/ab/optimize/multi-gen）在未配置端点时会在日志里打印明确的 `⚠️ …跳过：…` 原因，不再静默返回。

### 10.1 RD-Agent(Q) 官方循环（conda 环境 + qlib docker 沙箱）

循环本体在 conda 环境 `rdagent` 的子进程里运行，回测在 docker 容器
`local_qlib:latest` 中执行，两者参数都由 `config.RDAGENT_QLIB_DOCKER_ENV`
注入，可用环境变量覆盖：

| 环境变量 | 默认 | 作用 |
| :--- | :--- | :--- |
| `ETF_RDAGENT_ENV` | `rdagent` | 运行 rdagent/pyqlib 的 conda 环境名 |
| `ETF_RDAGENT_TIMEOUT` | `7200` | 子进程最长秒数，超时即回收并保留部分产物 |
| `ETF_RDAGENT_EXEC_ENV` | `docker` | 因子工作区 `qrun` 后端；`conda` 需宿主再装一份 `rdagent4qlib` 环境 |
| `ETF_RDAGENT_DOCKER_GPU` | `false` | 容器是否用 GPU（本机 GPU 2GB 不可用，保持 false） |
| `ETF_RDAGENT_DOCKER_SHM` | `4g` | 容器共享内存（rdagent 默认 16g = 本机物理内存上限，容器起不来） |
| `ETF_RDAGENT_DOCKER_MEM` | `10g` | 容器内存上限（rdagent 默认 48g，OOM 时只表现为非零退出码） |
| `ETF_RDAGENT_DOCKERFILE_DIR` | `data/results/rdagent_docker` | 沙箱镜像构建目录；rdagent 每次循环都按此目录无条件重建 |

镜像构建目录里的 `Dockerfile` 有三处本机专用修正，重建/换机时必须保留：

1. 基础镜像用 `python:3.10-slim` 而非官方 `pytorch/pytorch:*-cuda*`——factor
   循环的回测模型是 `conf_baseline.yaml` 的 qlib `LGBModel`（纯 CPU LightGBM），
   且 docker hub 直连不通、`pytorch/pytorch` 不在国内代理白名单；
2. `ENV MLFLOW_ALLOW_FILE_STORE=true`——mlflow 3.x 把 qlib 默认使用的
   `./mlruns` 文件后端判为维护模式并直接抛 `MlflowException`，容器内看不到
   宿主机变量，只能烤进镜像；
3. `"cvxpy<1.4"`——不钉版本会装到 ≥1.4，其 canonicalizer 引用
   `scipy.sparse.eye_array`（scipy ≥1.14 才有），与 qlib 锁定的
   `scipy==1.11.4` 互斥，在导入组合优化策略时抛 `ImportError`。

`~/.qlib/qlib_data/cn_data` 必须是指向 `qlib_bin` 的**相对**软链：宿主
`~/.qlib` 会整体挂载进容器，绝对路径在容器内解析不到。

首次使用前还需预生成因子源数据（跳过 rdagent 官方脚本对成分数据的假设，
详见 §11）：

```bash
cd etf/v1/data/results/rdagent_output
env PYTHONNOUSERSITE=1 conda run -n rdagent \
    python ../rdagent_docker/pregen_source_data.py
```

循环产物落在 `data/results/rdagent_output/log/<会话>/__session__/`，驱动侧
`rdagent_driver._harvest_from_sessions` 从最新会话 pickle 回收因子（名字 +
LaTeX 原式 + `factor.py` + IC），翻译成管线 DSL 表达式后写成 `factors.json`
供 `official_rdagent._recover_factors` 读取；跑完可 `python main.py` 直接
复用，不必等回测指标。单 loop（6-8 个因子、4 步）在本机耗时约 1.7-2.5
小时，其中 LLM 代码演化占绝大部分。不重跑循环、只重新回收一次会话产物：

```bash
cd etf/v1/data/results/rdagent_output
env PYTHONNOUSERSITE=1 conda run -n rdagent python harvest_only.py
```

列名口径（已解决）：本地模型生成的 `factor.py` 普遍按 `df['close']` 取列，而
qlib 日线数据的原生列名是 `$close`，早期 running 步骤合并因子数据时会报
`No valid factor data found to merge` 并跳过该 loop（09-21 两轮实测均如此）。
现由 `pregen_source_data.py` 在预生成的两份 `daily_pv.h5` 里为每个 `$col` 追加
一份去 `$` 的别名列（`$close` 与 `close` 并存，幂等迁移，缺则补齐、齐则跳过），
两种取法都能命中。已用回收到的真实 `factor.py` 与 405M 全量 h5 验证：`execute`
全链路 rc=0 并落出 `result.h5`，整轮日志 `KeyError: 'close'` 0 命中。若重新预生成
数据，命令与下节 harvest 同样在 `rdagent_output` 目录下执行：

```bash
cd etf/v1/data/results/rdagent_output
env PYTHONNOUSERSITE=1 conda run -n rdagent python ../rdagent_docker/pregen_source_data.py
```

running 阶段官方 IC（当前取舍）：列名维度已解，但要让 rdagent 自己的 running
步骤稳定产出 IC，还需 LLM 可靠满足其因子 I/O 契约（`(datetime,instrument)`
是索引层级而非列、`result.h5` 格式、以及给出价格可算的合理假设）。09-21 实测：
把 chat 模型从通用 `qwen2.5:7b` 换成本地 `qwen2.5-coder:7b`（同尺寸同速度，`.env`
改 `LITELLM_CHAT_MODEL=ollama_chat/qwen2.5-coder:7b`，embedding 保持
`ollama/nomic-embed-text`）后，`pd.np` 一类 pandas-2 语法 bug 归零，但 7B 档仍会
犯「把 MultiIndex 当普通列」「生成 `SMA(factor)` 退化元因子假设」等错，running
未稳定出 IC。本机受 16G 内存 / CPU-only 限制，跑不动 14B+，也不接 API，故**暂以
「回收因子定义（名字 + LaTeX/DSL）+ 管线侧自算 IC」为稳态收口**，不再为官方
running IC 追加跑圈。环境链路本身已通（同容器 `qrun conf_baseline.yaml` 全市场
跑通、ICIR=0.227）。注意：回收因子的 `expr` 只有在名字/公式能明确解析出作用列时
才非空（如「…of Volume」）；泛化名「20-day Simple Moving Average」当前映射不到
DSL，会被 `_attach_impl` 跳过、不计入主线——主线因子仍由自身 GP/DSL 生成兜底。

## 11. 常见问题排查

| 症状 | 原因与处理 |
| :--- | :--- |
| `ModuleNotFoundError` | 未在 `etf/v1/src` 目录运行，或绕过入口脚本直接 import 子模块。cd 到 src 并用 `run_*.py` / `main.py` 启动 |
| akshare 装不上 | Python 版本 < 3.10，升级或 `pip install -U akshare` |
| 行情拉取失败/标的数骤减 | 东财接口波动，重跑（有缓存）；持续失败可减小 `ETF_FILTER.max_count` |
| 早年回测空仓/标的少 | 池每指数取**上市最早**代表并要求成立满 1 年，历史覆盖已尽量前移；起点仍早于多数标的上市日时早年无标的属客观事实（指数化 ETF 本身晚于指数出现） |
| 跑得太慢 | 关闭 `MULTI_SOURCE/GENETIC/GENETIC_MULTI_OBJECTIVE/LLM_GENETIC_HYBRID/MULTI_STRATEGY/WALK_FORWARD`；分钟线缩小 `BACKTEST_START` |
| 因子库 git 提交到了主仓库 | `FACTOR_LIBRARY_GIT.enabled=False` 关闭自动提交（其 `git_dir="."` 指向 src 外层仓库） |
| 报告没出现在 report/ | 确认命令跑对入口；`ls etf/v1/report`；设置 `ETF_REPORT_DIR` 时以该变量为准 |
| LLM 输出是模板文字 | 未配置 API Key 且未设 `ETF_LLM_BASE_URL`，属预期降级；本地部署 Ollama 后 `export ETF_LLM_BASE_URL=http://localhost:11434/v1 ETF_LLM_MODEL=qwen2.5:14b` 即可 |
| RD-Agent(Q) 未运行 | 日志"前置检查"逐项列出缺失依赖（conda/docker/pyqlib/LLM 端点/qlib 沙箱镜像）；按微软官方文档装齐后自动真跑 factor 循环，缺失期间降级本地管线不影响其余阶段 |
| 循环卡在 `Building the image from dockerfile` 上百分钟 | rdagent 每次运行都按 `QLIB_DOCKER_DOCKERFILE_FOLDER_PATH` 目录无条件重建镜像且不回显进度。确认该变量指向本仓库 `data/results/rdagent_docker`（CPU slim 版，命中缓存约 3 分钟）；若指向 site-packages 里的官方 CUDA 版则需重编 GB 级层，也可 `QLIB_DOCKER_BUILD_FROM_DOCKERFILE=false` 直接用已有镜像 |
| 容器起不来 / 循环以非零码退出但无原因 | 多为 `shm_size`/`mem_limit` 超本机内存，见 §10.1 的 `ETF_RDAGENT_DOCKER_SHM` / `ETF_RDAGENT_DOCKER_MEM` |
| `qrun` 抛 `MlflowException: filesystem tracking backend ... maintenance mode` | mlflow ≥3 封了 qlib 默认 `./mlruns` 后端；镜像需 `ENV MLFLOW_ALLOW_FILE_STORE=true`（§10.1） |
| `ImportError: cannot import name 'eye_array' from 'scipy.sparse'` | cvxpy ≥1.4 与 qlib 锁定的 `scipy==1.11.4` 冲突；镜像需 `cvxpy<1.4`（§10.1） |
| `AssertionError: daily_pv_debug.h5 is not generated` | 官方生成脚本假定其 100 只调试标的均有行情，本数据包含退市无数据标的（SH600001/003/005/087/102）。跑 §10.1 的 `pregen_source_data.py` 预生成两个数据目录即绕过（该步硬编码走 docker，无法用配置跳过） |
| 看板无数据 | 先完成一次回测（app.py 读 src 下 CSV）；反馈看板先跑 `run_feedback.py` |
| pandas FutureWarning(stack) | 无害提示，可忽略 |
| 自动重挖从不触发 | 看日志 `DSR/PBO 联动:` 与 `未触发自动重挖：…` 两行的原因；连续轮数与冷却依赖 `data/cache/remining_state.json`，删该文件即当作首轮从零计数 |
| `run_feedback.py` 抛 `KeyError: 'datetime'`（或 `'date'`） | 反馈侧曾写死回测成交表的时间列：日线产物用 `date`、分钟线用 `datetime`，另一种频率下即崩。现已自动识别两列（`turnover_analyzer` / `live_attribution`），遇到该报错说明跑的是旧代码 |
| 实盘风控参数与研究结论不一致 | 检查 `data/results/optimized_params_{freq}.json` 是否存在（研究第 9 阶段落盘）；缺失时 `run_live.py` 打印 `⚠️ 未找到研究侧调参产物` 并退回 `config_live` 默认值。两频率的产物互不共用（文件名带频率后缀） |
